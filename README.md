# Week1Task29 — Локальный LLM-чат + оптимизация локальной LLM

Веб-приложение для общения с **локальной** LLM через сервер **Ollama**
(`http://localhost:11434`) и инструменты оптимизации модели под конкретную
задачу: настройка параметров генерации, квантование, prompt-шаблоны, сравнение
«до/после» с отчётом.

> ⚠️ **Важно про папку и репозиторий.**
> Локальная рабочая папка проекта — **`C:\1C\Тестирование ИИ Проект\Week1Task27`**
> (проект развивается в ней, начиная с Дня 27). При этом на GitHub код
> публикуется в репозиторий **`Week1Task29`** (требование Дня 29).
> Так сделано намеренно, чтобы не создавать новую локальную папку.

Работает полностью офлайн — облачные модели не используются.

**День 27 (база):**

  `/unload`, `/status`, `/export`, `/reset`) из единого реестра.
- 🧯 Понятные русские сообщения об ошибках; логи в `logs/app.log`.

**День 29 (оптимизация):**
- 🎛️ Панель **«Параметры генерации»**: `temperature`, `top_p`, `top_k`,
  `repeat_penalty`, `num_predict`, `num_ctx`, `seed` + сброс к дефолтам.
- ✍️ Управление **системным промптом** (textarea, сохранить/сбросить).
- 💾 **Профили** (JSON): сохранить текущий набор (модель + промпт + параметры),
  загрузить, удалить.
- 🏷️ **Кастомные модели через Modelfile** (`ollama create`) с «зашитыми»
  SYSTEM и PARAMETERS: `week1task29-1c-baseline`, `week1task29-1c-optimized`,

- 📊 **Сравнение «до/после»**: `tools/compare.py` прогоняет тестовые запросы по
  конфигурациям, замеряет скорость/ресурсы, оценивает качество через
  **LLM-as-judge** и формирует отчёт `reports/REPORT_*.md`.
- 📈 Метрики: токены/с, время генерации и загрузки, пиковая VRAM/RAM,
  стабильность (дисперсия ток/с).

## Системный промпт: как учитывается и приоритет

Системный промпт добавляется к **каждому** запросу первым сообщением
(`{"role": "system", ...}`) и уходит в Ollama вместе с историей диалога.

**Приоритет (проверено эмпирически):**

1. Если в приложении задан **непустой** системный промпт (панель → «Системный
   промпт» → «Сохранить», или команда `/system <текст>`), он становится
   системным сообщением модели и **перекрывает** `SYSTEM` из Modelfile
   кастомной модели (`week1task29-1c-*`).
2. Если системный промпт в приложении **пустой**, Ollama использует `SYSTEM` из
   Modelfile (для кастомных моделей) или обходится без него (для базовых).

**Важно:** промпт не «переписывает» прошлое. Уже накопленные пары
«вопрос–ответ» остаются в истории и влияют на ответ сильнее нового промпта —
поэтому после смены промпта **очистите чат** (`/clear` или кнопка «Очистить
чат»), иначе разница может быть незаметна. Приложение теперь само напоминает
об этом подсказкой после изменения промпта при непустой истории.

Проверка (модель `gpt-oss:20b`, вопрос «Сколько будет 2+2?»):

| Системный промпт | Ответ |
|---|---|
| пусто | `2+2=4` |
| «Answer only in English…» | `2 + 2 = 4` |
| «Отвечай только стихами, в рифму.» | `Четыре — ответ, как дважды два, в рифму звучит, как в сказке.` |
| «Ты — пират… добавляй «Аррр!».» | `Аррр! 2+2 равно 4.` |

## API-эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | Веб-интерфейс |
| GET | `/api/status` | Статус: Ollama, модель, история, аптайм |
| GET | `/api/models` | Модели Ollama + текущая |
| POST | `/api/model` | `{ "name": "..." }` — переключение + выгрузка старой |
| POST | `/api/unload` | Выгрузка текущей модели |
| GET/POST | `/api/system` | Получить/задать системный промпт |
| **GET/POST** | **`/api/params`** | **Текущие параметры генерации / обновление (валидация диапазонов)** |
| **GET** | **`/api/profiles`** | **Список профилей** |
| **POST** | **`/api/profiles`** | **`{ "name", "params", "system" }` — сохранить профиль** |
| **POST** | **`/api/profiles/load`** | **`{ "name" }` — применить профиль** |
| **POST** | **`/api/profiles/delete`** | **`{ "name" }` — удалить профиль** |
| **POST** | **`/api/compare`** | **Ручной запуск сравнения (`tools/compare.py`) в фоне** |
| POST | `/api/chat` | `{ "message", "stream", "params?" }` — SSE-поток или JSON |
| POST | `/api/clear` / `/api/reset` | Очистка истории / полный сброс |
| GET | `/api/export` | JSON с историей (файл на скачивание) |
| GET | `/api/help` | Справка по командам из реестра |

`POST /api/chat` принимает **опциональный** набор параметров (`params`) — клиент
может передать свои значения, иначе используются серверные (параметры сессии).

## Инструменты оптимизации (`tools/`)

### 1. Создание кастомных моделей

```powershell
python tools/create_model.py                       # все три конфигурации
python tools/create_model.py --configs baseline,optimized
python tools/create_model.py --dry-run             # только Modelfile
```
Генерирует `modelfiles/week1task29-1c-*.Modelfile` (FROM + SYSTEM + PARAMETERS)
и вызывает `ollama create <имя> -f <Modelfile>`. Проверка: `ollama list`.

### 2. Сравнение «до/после»

```powershell
python tools/compare.py --profile 1c_support --configs baseline,optimized,qat --seed 42
```
Результаты: `reports/raw_<timestamp>.json` и `reports/REPORT_<timestamp>.md`
(сводные таблицы, side-by-side, оценки судьи, ресурсы, выводы).

### 3. LLM-as-judge (отдельно)

```powershell
python tools/judge.py --query "..." --a "ответ A" --b "ответ B" --key-points "п1;п2"
```

### 4. Метрики ресурсов

```powershell
python tools/resources.py           # текущая VRAM/RAM
python tools/resources.py --unload  # выгрузить все модели из VRAM
```

**Конфигурации сравнения** (профиль `1c_support`):

| Ключ | Базовая модель | Промпт | Параметры |
|---|---|---|---|
| `baseline` | `gpt-oss:20b` | generic (День 27) | temp 0.7, num_ctx 4096, num_predict −1 |
| `optimized` | `gemma3:12b` | 1С-поддержка | temp 0.2, top_p 0.9, top_k 40, repeat 1.1, num_predict 512, num_ctx 8192 |
| `qat` | `gemma3:12b-it-qat` | 1С-поддержка | как optimized (сравнение квантования Q4_0 QAT) |

## Обработка ошибок

| Ситуация | Сообщение |
|---|---|
| Ollama недоступна | «Локальный сервер Ollama не запущен. Запустите C:\LLM\Ollama\ollama.exe serve» |
| Модель не найдена | «Модель <имя> не найдена. Доступные: …» |
| Таймаут | «Запрос превысил время ожидания…» |
| Превышен контекст | подсказка увеличить `num_ctx` / очистить историю |
| Неверный параметр | «Некорректное значение для <ключ>: …» / ошибка валидации диапазона |
| Прочее | текст без трейсбэка (трейсбэк — в `logs/app.log`) |
